# 品牌 VPN 产品架构（规划，不代表已实现）

## 现阶段（本 ZIP 已包含）

- `lib/` Flutter Android + Windows 客户端起步源码；通过第三方插件和 sing-box 核心承载连接。
- `lib/brand.dart` 客户端统一品牌文字及色彩。
- `website/` 静态中文品牌官网，可在本地预览并自行部署静态站点。
- `website/assets/logo.svg` 和 PNG 输出是临时品牌图标，注意系统应用启动图标仍需分别适配。
- 无账号系统、无订阅计费、无运营后台、无可用节点、无已发布安装包。

## 未来运营系统（未开发）

```text
支付机构（未来） ---> Webhook 核验 -> 订单状态 -> 订阅权限
```

## 关键设计原则

1. **客户端与服务器分离**：客户端本身不提供节点，也不出售网络带宽。服务器实际运行位置、运营许可与网络成本由运营方负责。
2. **账户系统可选**：用户自己导入节点时不需要你搭建中心化账号系统。若以后收费和集中管理，采用服务器签发的有时效、可撤销凭据，而不是把所有节点私钥嵌入 APK。
3. **密钥保护**：订阅令牌应为随机不可猜测的机密，数据库尽量只保存不可逆哈希值；通过 HTTPS 传输；允许轮换、吊销；支付 Webhook 必须验证签名。
4. **数据最小化**：仅采集运营必需信息，明确日志策略、账号注销及数据保留期限，不承诺未经验证的“零日志”。
5. **系统安全**：Android VpnService、Windows TUN/系统代理、DNS、IPv6、断线行为、配置切换和崩溃恢复必须分别验证。
6. **开源许可**：现有 sing-box / flutter_sing_box 的 GPL-3.0 授权必须满足；商用不意味着自动可以闭源分发。品牌不应暗示与 sing-box 官方关联。
7. **运营合规**：核实部署地与用户所在地规定、VPN/网络服务合规要求、税务和消费者权益；Android 上架 Google Play 还需遵守 VpnService 政策。

## 后续建议的 API（仅设计参考）

- `POST /v1/auth/register` / `POST /v1/auth/login` — 身份验证、限速、防撞库与 MFA。
- `GET /v1/me` — 用户资料，含权限；不返回任何其他用户信息。
- `GET /v1/subscriptions/current` — 查看套餐和到期信息。
- `GET /v1/profiles` — 对有权访问的账号签发短期、可撤销的配置请求。
- `POST /v1/devices` — 注册、撤销受限设备标识；遵守个人数据政策。
- `POST /v1/payments/webhook` — 验证支付平台签名，更新订阅权益。
- 管理端单独域名和授权，带操作审计、二步验证及最小权限控制。

上述接口 **没有随本包部署**，不可在网站上宣称用户可注册、购买或登录。
