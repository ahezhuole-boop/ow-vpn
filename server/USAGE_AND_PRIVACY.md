# 使用自己的节点：只看流量用量、不存访问日志的设计

## 可实现的目标（未部署，也不代表已验证）

客户端使用你运营的 VPS；运营方后台仅显示：账号代号、累计上传字节、累计下载字节、套餐总量/剩余量。不在自有业务数据库中存逐连接、目的地址、网址、DNS 查询、使用时间线或内容记录。

**这些账号代号与用量计数器仍是数据，不是“什么数据都不收集”；要展示长期累计值就必须保存累计字节数。** 严格的“完全不保留任何数据”只能显示当前瞬时/内存统计，重启即丢失。

## 需要分别配置与审计的层次

1. **VPN 内核**：sing-box 服务端配置顶层 `"log": {"disabled": true}`，需确认当前服务实际加载该配置。客户端配置亦禁用该内核日志。
2. **流量统计**：采集每个账号的上传/下载字节计数器，仅保存数值与必要的账号代号；不采集逐连接数据。不同协议的逐账号流量统计方式不同，可能需要节点管理系统。
3. **服务器**：核实 systemd journal、Nginx/Caddy、反向代理、SSH、安全软件、控制面板、DNS 组件和内核审计等是否另写访问/连接日志；请勿未经评估关闭所有安全告警。
4. **云服务商和上游网络**：服务商可见服务器公网 IP、进出流量及部分元数据，且可能有独立法定留存要求，你不能替第三方保证零日志。
5. **移动端和桌面端**：检查应用诊断、崩溃报告、SDK 遥测、本地缓存、订阅源及其 HTTPS 服务端的日志。单独关闭 sing-box 日志不证明完全不记录。

## 适合的隐私表述（须验证后才可公开）

“我们不主动保存浏览历史、访问域名、DNS 查询记录或连接活动日志；为提供套餐流量统计，我们保存账号代号和累计使用字节数。云服务商及操作系统可能另外处理网络元数据。”

避免宣传“绝对匿名”“100% 零记录”“任何人都无法看到 IP”。
